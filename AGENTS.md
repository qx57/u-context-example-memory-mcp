# Работа с проектом

Проект хранит опыт одного локального агента, который создаёт и запускает функциональные тесты REST API. Spring Boot предоставляет MCP, REST и интерфейс оператора. Python-адаптер использует Mem0 OSS, а Qdrant хранит наблюдения и векторы.

## Документы

- [Исходная идея](docs/000.Project_idea.md) задаёт назначение и технические ограничения.
- [Архитектура](docs/001.Architecture.md) описывает компоненты, модель памяти и принятые решения.
- [Контракты](docs/002.Contracts.md) описывают MCP-инструменты, REST API, схему оценки и ошибки.
- [План реализации и проверки](docs/003.Implementation.md) описывает конфигурацию, эксплуатацию, критерии приёмки и открытые параметры.

## Код и запуск

- [Spring Boot и MCP](src/main/java/local/memory/MemoryApplication.java), [Python-адаптер](src/main/resources/adapter/worker.py) и [Docker Compose для Qdrant](deployment/compose.yaml).
- [Сквозная проверка](tests/smoke.py) использует отдельную коллекцию в локальном Qdrant и подставляет локальный OpenAI API. Команда приведена в [документации запуска](docs/003.Implementation.md).

## Практика работы

- При изменении поведения обновляйте затронутые контракты, описание архитектуры и критерии проверки вместе с реализацией.
- При изменении MCP, Mem0 или Qdrant сверяйте интеграцию с закреплёнными версиями и первоисточниками, указанными в документации.
- Используйте обезличенные примеры. Храните ключи в настройках MCP-клиента вне репозитория. В диагностике указывайте идентификатор операции, время и код ошибки.
- Проектные скрипты, скилы и постоянные пути для логов добавляйте в этот указатель по мере их появления. JVM и Python отправляют диагностические сообщения в `stderr`, откуда их может собирать MCP-клиент.
